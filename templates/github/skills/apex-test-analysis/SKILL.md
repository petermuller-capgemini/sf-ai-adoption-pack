# Apex Test Analysis

## Purpose

Provides three complementary scripts for end-to-end Salesforce Apex test analysis:

1. **Aggregate coverage** — Merge coverage JSON / JUnit XML into a single CSV summary.
2. **Parse test results** — Convert the human-readable `test-result.txt` into a normalised CSV.
3. **Process test runs** — Run Apex tests per class, collect coverage over time, and generate Excel + graphs.

## Scripts

All scripts live under `.github/skills/apex-test-analysis/scripts/`.

### aggregate_test_coverage.py

Aggregate code-coverage JSON outputs (or JUnit XML) into a CSV summary.

```bash
# Scan a folder of test-result / coverage artifacts
python3 .github/skills/apex-test-analysis/scripts/aggregate_test_coverage.py \
  --input-dir test_results \
  --output-file test_results/coverage_summary.csv

# Read a single coverage JSON (compact output)
python3 .github/skills/apex-test-analysis/scripts/aggregate_test_coverage.py \
  --coverage-file test_results/test-result-codecoverage.json \
  --output-file test_results/coverage_summary.csv
```

**Output columns (full mode):**
`class`, `total_lines`, `covered_lines`, `non_covered_lines`, `covered_percent`,
`test_classes`, `total_test_time_seconds`, `passing_methods`, `failing_methods`, `error_messages`

**Output columns (single-file mode):**
`class`, `total_lines`, `covered_lines`, `covered_percent`

Tolerates multiple JSON shapes produced by different Salesforce CLI versions.

### test_results_to_csv.py

Parse the human-readable `test-result.txt` produced by `sf apex get test` into a
normalised CSV.

```bash
python3 .github/skills/apex-test-analysis/scripts/test_results_to_csv.py \
  --input test_results/test-result.txt \
  --output test_results/test_details.csv
```

**Output columns:**
`test_class`, `test_method`, `class_tested`, `outcome`, `percent`, `message`, `runtime`

The parser handles rows where `class_tested` is absent and stops parsing when it
reaches the coverage section header.

### process_apex_tests.py

Higher-level orchestrator that:

1. Reads `code-quality/classes.csv` (generated by the **salesforce-code-quality** skill).
2. Runs `sf apex run test` for each test class.
3. Appends date-stamped passing/failing/coverage columns to the CSV.
4. Generates an Excel workbook with Data, Coverage (wide), Coverage (long) sheets.
5. Produces a coverage-progress graph embedded in the workbook.

```bash
python3 .github/skills/apex-test-analysis/scripts/process_apex_tests.py
```

**Prerequisites:** `pandas`, `matplotlib`, `openpyxl` (install via `pip install pandas matplotlib openpyxl`).

**Configuration** (edit constants at the top of the script):

| Constant     | Default                             | Description                      |
| ------------ | ----------------------------------- | --------------------------------- |
| `INPUT_CSV`  | `code-quality/classes.csv`          | Class inventory CSV              |
| `OUTPUT_DIR` | `test_results`                      | Where `sf` writes test artifacts |
| `EXCEL_PATH` | `code-quality/classes_results.xlsx` | Output Excel file                |
| `GRAPH_DIR`  | `code-quality/graphs`               | Graph image output directory     |

### json_to_csv.py

Quick converter that turns a Salesforce coverage JSON file into a flat CSV.
Hardcoded to read `qa-result/test-result-codecoverage.json` by default.

```bash
python3 .github/skills/apex-test-analysis/scripts/json_to_csv.py
```

**Output columns:** `name`, `totalLines`, `totalCovered`, `coveredPercent`

**Output file:** `qa-result/test-result-codecoverage.csv`

> **Note:** For more flexible coverage aggregation (custom paths, multiple input
> formats), prefer `aggregate_test_coverage.py` instead.

## Typical Workflow

```bash
# 1. Fetch test results from a completed test run
sf apex get test --test-run-id <ID> \
  --detailed-coverage --code-coverage \
  --result-format human --output-dir test_results

# 2. Parse the human-readable results
python3 .github/skills/apex-test-analysis/scripts/test_results_to_csv.py \
  --input test_results/test-result.txt \
  --output test_results/test_details.csv

# 3. Aggregate coverage
python3 .github/skills/apex-test-analysis/scripts/aggregate_test_coverage.py \
  --input-dir test_results \
  --output-file test_results/coverage_summary.csv

# 4. (Optional) Run full batch + Excel/graphs
python3 .github/skills/apex-test-analysis/scripts/process_apex_tests.py
```

## Interaction Protocol

- **User input**: Use `vscode_askQuestions` for any confirmation or clarification needed mid-workflow. Never stop and wait for a follow-up prompt.
- **Session end**: Confirm with the user via `vscode_askQuestions` before ending the session.
- **Subagents**: Offload heavy analysis to subagents. Tell them: *"Return only key findings. Be concise — no verbose explanations, no raw data."*
